# Contributing to Atomdrift Scan

Thanks for helping. Bug reports, detection misses, false positives and pull
requests are all welcome. For security vulnerabilities, see
[SECURITY.md](SECURITY.md).

## Toolchain

- Rust **1.97** or newer (`rust-version` in Cargo.toml) builds the crate.
- CI lints and builds releases with **1.99.1** (`RUST_TOOLCHAIN` in
  `.github/workflows/ci.yml` and `build.yml`). Use the same version locally,
  for example `rustup override set 1.99.1`, because clippy's lints change
  between releases.
- A C/C++ toolchain: several dependencies (UnRAR, jemalloc, tree-sitter) build
  C or C++ code.
- GNU make. On Windows the Makefile finds Git for Windows' `sh` itself.

## Build, lint, test

```sh
make            # debug build
make lint       # cargo fmt --check, clippy -D warnings, rustdoc -D warnings
make test       # cargo nextest (if installed) + doctests, else cargo test
make release    # optimized build into out/atomscan (no PGO by default)
make install    # make release, then install atomscan on your PATH
```

`make lint` and `make test` must pass before a change is merged; CI runs the
same targets. `make fix` applies the fixes clippy and rustfmt can make on their
own.

`make install-precommit` installs `scripts/pre-commit` as a git hook. Before
each commit it refuses local dependency overrides (`scripts/check-lock.sh`),
then runs `make test`, `make lint` and `atomscan validate`. Skip it for a single
commit with `git commit --no-verify`.

### Tests that need a model bundle

Tests that need trained models are `#[ignore]`d and say what they need in the
ignore reason. Most read `SCAN_MODELS_DIR`, which can point at the bundle
`atomscan update-rules` installs (`atomdrift/scan/models/azoth` under your
platform's data directory):

```sh
SCAN_MODELS_DIR=~/.local/share/atomdrift/scan/models/azoth \
  cargo test --test scan_no_deadlock -- --ignored
```

A few need more: `AZOTH_DIR` (a full azoth ensemble checkout), or
`SCAN_PARITY_CASES` / `SCAN_BLEND_PARITY_CASES` (parity fixtures generated by
the model-training tooling). Run `grep -rn '#\[ignore' src tests` to list them.

## Sibling crates

Much of the analysis lives in sibling repositories that Cargo.toml pulls as git
dependencies: [cleave](https://github.com/atomdrift-project/cleave), fletch,
burton, proclist and filefacts, all under
[atomdrift-project](https://github.com/atomdrift-project). To test a change in
one of them, check it out beside this repository and point Cargo at it with a
`[patch]` in a throwaway config file (`cargo build --config patch.toml`)
rather than editing Cargo.toml. Never commit a local path override: the CI
`guard` job and the pre-commit hook reject it, because nobody else could build
the result. Land the sibling change first, then update `Cargo.lock` here.

## Pull requests

- Keep each pull request to one change, with a short imperative subject
  line, and say why in the description.
- Add or update tests with behaviour changes.
- Add a line to [CHANGELOG.md](CHANGELOG.md) for anything a user would notice.
- Never commit or attach live malware. Describe a sample by its SHA-256 and
  where it can be found.
